# Codebase Review Extension

Bundles the entire cfd2 project source into a **Gemini context cache**, then lets
you ask unlimited review questions against that cached context at ~75% reduced
input-token cost.

## Prerequisites

- A Gemini API key, provided via any of:
  1. **Pi login:** `/login google` (OAuth — no env var needed)
  2. **Pi models.json:** `GOOGLE_API_KEY` configured for the `google` provider
  3. **Environment variable:** `GEMINI_API_KEY`
- A Gemini model with large context window (default: `gemini-3.1-pro-preview`)

## How it works

1. **`/review-init`** collects all `.rs`, `.wgsl`, `.toml`, `.md` source files
2. Strips blank lines, comments, `#[cfg(test)]` blocks to minimize tokens
3. Counts tokens via Gemini API
4. Creates a **cached content** that persists server-side (default: 1 hour TTL)
5. **`/review <question>`** sends your question to Gemini, which reads the
   cached codebase context at the discounted cache-read price

## Commands

| Command | Description |
|---------|-------------|
| `/review-init` | Build the codebase cache |
| `/review <question>` | Ask a question against the cached codebase |
| `/review-ask <file.md>` | Batch-ask questions from a markdown file |
| `/review-files` | Preview which files would be cached |
| `/review-status` | Show cache status (tokens, expiry, model) |
| `/review-clear` | Delete the cache early |

## `/review-init` options

```
/review-init [--model MODEL] [--strip aggressive|moderate|none] [--ttl SECONDS] [--exclude PATTERN,...]
```

- `--model` — Gemini model ID (default: `gemini-3.1-pro-preview`)
- `--strip` — How aggressively to minimize source:
  - `aggressive` (default) — remove blanks, comments, `#[cfg(test)]`, block comments
  - `moderate` — remove blanks and `#[cfg(test)]` only
  - `none` — raw files
- `--ttl` — Cache time-to-live in seconds (default: 3600 = 1 hour)
- `--exclude` — Comma-separated additional patterns to exclude (e.g. `meshgen/,ui/`)

## Cost model

For a ~700K token codebase with Gemini 2.5 Pro:

| Action | Without cache | With cache |
|--------|--------------|------------|
| Cache creation (one-time) | — | ~$3.15 |
| Each review question (input) | ~$1.75 | ~$0.22 |

Cache pays for itself after **~2 questions**.

## Example workflow

```
/review-init
/review What are the main architectural modules and how do they interact?
/review Are there any potential race conditions in the GPU dispatch code?
/review What error handling patterns are used and are there gaps?
/review-clear
```

## Batch review

Create a file with questions (one per line, prefixed with `- `, `## `, or `1. `):

```markdown
- What are the main architectural modules?
- Are there any unsafe code patterns?
- How is error handling structured?
- What are the potential performance bottlenecks?
```

Then run:
```
/review-ask review-questions.md
```

Output is saved to `target/review-output.md`.

## Default exclusions

- `target/`, `.git/`, `.idea/`, `.code/`, `.kimi/`, `.pi/`, `node_modules/`
- `bindings.rs` (auto-generated by wgsl_bindgen, ~38K lines)
- Test files under `tests/` directory
- `.md` files only from project root (not subdirectories)
